# PRD — autopass

წყარო: რეპოს კოდი, `memory.md`, `fix.md`, `lending/README.md`, `gewash/index.html` და git ისტორია (`d14001c` … `dfe84dc`). ცალკე დამტკიცებული metrics ან roadmap რეპოში არ არის.

## პროდუქტი

autopass არის მანქანის რეცხვის სერვისი. კლიენტი ირჩევს ფილიალს, ჯავშნის რეცხვას, ყიდულობს პაკეტს და ქულებით იღებს ვაუჩერს ან ბილეთს. ფილიალის მენეჯერი QR-ს ამოწმებს და ჩანაწერის სტატუსს ცვლის. ადმინი Laravel-ის Blade დაფიდან მართავს ფილიალებს, პაკეტებს, კლიენტებს და კორპორატიულ ავტოპარკს.

ინტერფეისის სახელია **autopass** (`gewash/index.html`: „რეცხვის პაკეტი და ჯავშანი“). `gewash/package.json`-ის `name` კვლავ `autolime`-ია. ცოცხალი კოდი შემოვიდა `wash.socialsave.cc`-დან (`d14001c`, 2026-10-07). Push-ის ნაგულისხმევი მისამართი კვლავ `https://app.geocar.ge/messages`-ია (`User::sendPush`). მარკეტინგის გვერდი აპზე მიდის `lending/config.js`-ის `window.AUTOPASS_APP_BASE`-ით (`https://wash.socialsave.cc`).

## პრობლემა

რეცხვის ჯავშანი, პაკეტის QR და ფილიალის დადასტურება ერთ ანგარიშზე უნდა იჯდეს. კლიენტს სჭირდება ფილიალი, დრო, მანქანა და გადახდა. მენეჯერს სჭირდება მხოლოდ თავისი ფილიალის ჩანაწერი. პარტნიორს სჭირდება ვაუჩერის შემოწმება. კომპანიას სჭირდება ავტოპარკის სია და ანგარიში.

## მიზნები

რეპოში რიცხვითი მიზნები არ წერია. კოდის ნაკადებიდან პროდუქტი ამას აკეთებს:

- ჯავშანი იწერება არჩეულ დღეზე და `H:i` დროზე (`AppointmentsController::addAppointment`).
- პაკეტი და ქულები იხდის Flitt-ით და TBC checkout-ით. დაბრუნება მიდის `{APP_URL}/payment-success`-ზე (`TbcCheckoutController::resultUrl`).
- QR-ს ხსნის მხოლოდ მენეჯერი, და მხოლოდ იმ ფილიალის ჩანაწერზე, რომელიც მას ეკუთვნის.
- ენა არის `ka`, `en`, `ru`. ახალ სესიაზე ნაგულისხმევია `ka`. ძველი `ge` იკითხება როგორც `ka`.
- კორპორატიული კლიენტი მართავს ავტოპარკს პანელიდან (`/partner`) და API-დან (`/api/corporate/vehicles`, Bearer ან `X-Api-Key`).

## მომხმარებლები

`users.role` (`User` მოდელი):

| როლი | მნიშვნელობა | სად შედის |
|---|---|---|
| კლიენტი | `User::ROLE_USER` = `0` | `gewash`, JWT `auth:api` |
| მენეჯერი | `User::ROLE_MANAGER` = `1` | იგივე აპის მენეჯერის ეკრანები |
| ადმინი | `User::ROLE_ADMIN` = `2` | `/dashboard`, სესია. რეგისტრაცია გამორთულია (`Auth::routes(['register' => false])`) |

ცალკე ცხრილები:

- **პარტნიორი** (`partners`) — voucher checker. JWT guard `auth:partners`. ლოგინი `POST /api/partner/login`.
- **კორპორატიული კლიენტი** (`corporate_clients`) — ავტოპარკი, Excel ანგარიში, API token. პანელი სესიით (`CorporatePanel`).

მარკეტინგის გვერდი (`lending/`) აუტორიზაციას არ იყენებს. App Store და Google Play ბეჯები `/register`-ზე მიდის, რადგან სტორში აპი არ არის (`lending/README.md`).

## ძირითადი ფუნქციები

ეს არის ის, რაც ახლანდელ `main`-ზე მუშაობს, და არა მომავალი სია.

**კლიენტი (`gewash/src/App.tsx`)**

- Splash, სანამ ენა და როლი ჩაიტვირთება. პირველ გასვლაზე 3-სლაიდიანი onboarding (`localStorage` გასაღები `autopass.onboarding.v4`).
- შესვლა `/auth`, რეგისტრაცია `/register`, პაროლის განახლება `/renew-password`, კონფიდენციალურობა `/privacy`.
- მთავარი, ფილიალები (სია და რუკა), ჯავშანი `/wash-appointment`, პაკეტები, ქულები, მაღაზია (ვაუჩერი და გათამაშება), QR, პროფილი, მანქანის დამატება/რედაქტირება, გამოხმაურება, შეტყობინებები, დახმარება, კონტაქტი, პარამეტრები (ენა, გამოსვლა, ანგარიშის წაშლა).
- ქვედა ნავი: მთავარი, კალენდარი, QR, ფილიალები, პროფილი. `/customer-calendar` ახლა `/shop`-ზე გადადის (`Navigate`).
- დესკტოპი `1024px`-დან: გვერდითა მენიუ (`DesktopSidebar`), სიგანე `268px`.
- რუკა ნაგულისხმევად სტატიკური დემოა. ცოცხალი PMTiles რუკა ირთვება `VITE_LIVE_MAP=true`-ით.

**მენეჯერი**

- კალენდარი `/`, ჩანაწერები `/booking`, გადატანა `/reschedule/:id`, სკანერი `/manager-qr-page`, სტატისტიკა `/carwash-statistics`, პროფილი, კონტაქტი, დახმარება, პარამეტრები.

**ადმინი (`backend/routes/dashboard.php`, პრეფიქსი `/dashboard`)**

- კლიენტები, მენეჯერები, ჩანაწერები, ფილიალები (`washings`), პაკეტები, კუზოვის ტიპები, ბრენდები, ვაუჩერები, ბილეთები, პარტნიორები, პრომო, რეცხვის ანგარიში, კორპორატიული კლიენტები.

**გადახდა და ფონი**

- Flitt webhook: `ANY /callback/flitt/payment`.
- TBC: `ANY /callback/tbc/payment`, დაბრუნება `ANY /payment/return`, sandbox `GET|POST /payment/sandbox`.
- cron (`backend/routes/console.php`): ყოველ წუთში SMS კოდების წაშლა, პაკეტის ვადა, მენეჯერის შეხსენება 15 წუთით ადრე. 14:00 — პაკეტი 3 დღეში მთავრდება. 15:00 — 1 დღით ადრე.
- Push: OneSignal (`config/OneSignal.php`, `PushService`).

**სხვა ზედაპირი**

- `gewash/voucher-checker` — პარტნიორის მინი-აპი. `POST` check აბრუნებს `temp_code`-ს, `POST` use იღებს SMS კოდს.
- `lending/` — სტატიკური გვერდი, კომპილაციის გარეშე. დესკტოპი `760px`-ზე ზემოთ, მობილური `760px`-ზე და ქვემოთ.

ღია ხარვეზები (ფული, ანგარიში, ბიზნეს ლოგიკა, `tsc -b`, landing-ის `#` ბმულები) ჩამოწერილია `docs/TASKS.md`-ში და `fix.md`-ში.
